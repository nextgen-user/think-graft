An output-head experiment · 17 November 2026

Reasoning loops,
three output rows.

I wanted to reduce reasoning loops without changing the transformer’s internal layers. A small classifier built into three output rows reached 55.2% on MATH-500. The full run also exposed a failure that the small tests had missed.

The useful simplification is where to edit. A reasoning model already has a token for ending its scratchpad: </think>. Instead of searching for internal layers to change, I fit a small classifier to its final hidden state and build that classifier into a few output-layer weights. Inference then uses an ordinary weights file.

The limit matters. This prototype is not a robust loop fix: 165 of 500 runs reached the token limit. In 163, thinking had already closed and the output kept going. Repeated closing tags are a substantial failure, not removed from the results. See the audit.

03 The small change


Read a signal. Edit its output row.


Before choosing a token, the model produces a vector called the hidden state. The output layer turns that vector into a score for each token. One row scores </think>; other rows score Wait and  Wait.



A linear probe is a classifier that scores this state with a dot product. If its weights are g, its score is gTh. Adding the probe to an output row builds that same calculation into the token’s existing score. No separate probe runs during generation.


ℓ′ⱼ = (wⱼ + αg)ᵀh = ℓⱼ + αgᵀh


For this 0.8B candidate, the stop row combines a re-checking probe with a loop-boundary probe. A third probe suppresses the two Wait tokens when the state resembles looping. It is an extension of post 1’s single-row stopping edit, not the exact same one-row model.


The actual three-row recipe
ℓ′end = ℓend + 12 gdoneᵀh + 24 gboundaryᵀh
ℓ′Wait = ℓWait − 4 gloopᵀh
The second equation applies to both spellings of Wait. Coefficients were selected using development problems, not benchmark answers. This is still a weight edit; the intervention is at the output head rather than inside the transformer blocks.
At a fixed hidden state, the logit changes are directly calculable. Top-k/top-p filtering and subsequent generation prevent an exact reconstruction of every edited trajectory from an original trace. All scores here come from live generation.







04 How it was fitted


A concrete example: 25 choose 2.


One fitting problem asks for C(25, 2). The base trace calculates 25 × 24 / 2 = 300, states “Final Answer: 300,” and then keeps going to the 16,384-token fit limit.


Calculation: 25 × 12 = 300.
Final Answer: 300.
…followed by further checking.


A fitting example, train/2006, not a held-out benchmark question. Recorded excerpt.


  1. Record the base model. Save its final hidden states while it reads its own reasoning traces.
  2. Label useful distinctions. Mark paragraph boundaries after an answer appears, and repeated-line regions; use other reasoning states as negatives.
  3. Fit the directions. Shrinkage linear discriminant analysis finds directions separating those groups. It is a linear-algebra fit with labels, not gradient descent or base-model retraining.
  4. Calibrate, then freeze. Fit on 80 MATH-training questions, select strengths on 16 separate training questions, and keep the chosen weights fixed throughout the benchmark.


The output location is easy to specify: known token rows, no search over internal layers. The data work is not trivial. Collecting traces can take hours; the matrix solve is the quick part. An answer appearing in text is also an imperfect label—it does not prove the model has finished checking it.







05 Relation to the earlier work


Same problem. A different place to intervene.


RikiyaT’s Astra experiment removes a loop-associated direction from two internal feed-forward matrices. Nathan’s LP follow-up finds a related sparse internal edit. Here, the transformer computation is kept intact and the final token scores are edited directly.


Both families use activations and can be state-dependent. “His is constant; ours is conditional” would be too broad: Nathan measured a near-constant effect for a particular LP edit. An ordinary checkpoint with no runtime hook is also a feature of his method, not unique to this one.


The practical advantage I’m testing is a more mechanical recipe: record final states, fit a classifier, write a few output rows. Comparable accuracy from that recipe is interesting even without a higher headline score.


Earlier 4B, DeepSeek and agent observations
The earlier single-row method was tested separately on Qwen3.5-4B and DeepSeek V4.1 Flash. On eight paired 4B math questions, both models got 8/8 while total tokens fell 54%. DeepSeek’s six shared solved questions used about 40% fewer total tokens. Agent examples showed selective thinking around planning, errors and new information.
Those are small exploratory studies with configuration caveats, not proof of universal transfer. Our local DeepSeek internal-layer interventions failed to shorten reasoning, but they were not a controlled reproduction of RikiyaT’s exact method. I cannot conclude his method fails on DeepSeek.
The algebra does not depend on a particular model size. Useful signals, calibration and quality do. Each model needs its own fit. Read the original experiments and limitations.


Related work already includes probe-guided stopping, activation directions controlling reasoning length, and NoWait token suppression. The contribution here is an output-weight implementation and its measurements, not the invention of early stopping.







06 What the criticism changed


Ending thinking is not enough.


The largest failure became clear only after the full run. The edited model closed thinking in 163 of the 165 capped cases, then continued in the answer. Across 407 responses it emitted 1,348,952 extra closing tags, around 17% of all generated tokens. The model has no hard phase gate; its stop boost can remain active after the first close.


The grader does not automatically reject capped runs. It extracts the last boxed answer after the last close, or from the full response if thinking never closed. An audit found no correct boxed answer anywhere in the 165 capped responses. Unboxed candidates may still go uncredited under this protocol.


A cheap 8-gram detector, applied to saved outputs, flagged all 165 capped runs and 206 of 335 completed runs. That is alert coverage, not independently annotated precision/recall. It does not establish that forcing a stop at the alert would produce the right answer.


Completed checks, open controls, and selection caveats
  • Done: complete MATH-500; separate fitting/development IDs; frozen weights; exact tensor comparison; sampler checks; capped-answer audit; a prefix-only repetition diagnostic; published raw results.
  • Still missing: tuned penalty/sampling controls, avg@8 or larger repeated draws, independently labeled detector precision/recall, and systematic batch-invariance checks.
  • Presence penalty 1.5 is enabled. That is one setting, not a calibrated penalty sweep. A fixed seed does not remove serving noise.
  • The development set was reused for model selection. A fresh 16-question check scored 8/16 for this candidate versus 9/16 for the previous graft. This negative result is retained.
  • The earlier p = 0.0078 referred to token reductions on eight exploratory Qwen-4B pairs, not an accuracy improvement or a test that excludes sampling and serving noise.
  • Qwen’s tied embedding/head requires a new output matrix: roughly 0.51 GB extra. There is no extra transformer pass, but it is not zero memory overhead.
  • The current three-row model can change non-stop token choices. It must not be described as the old “only one logit changes” model.
